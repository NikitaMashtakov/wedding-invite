# Приглашение на свадьбу — автономная копия

Статическая копия `https://wedwed.ru/sitemaker/demo/20282/`, восстановленная из
Ctrl+S-сохранения. Внешних запросов нет: шрифты, стили, скрипты и фотографии
лежат в репозитории. Все пути относительные, поэтому сайт одинаково работает и
в корне домена, и в подкаталоге (GitHub Pages).

## Стек

Никакой сборки и фреймворков — это исходный шаблон wedwed.ru:

| | |
|---|---|
| Разметка | статический HTML (один `index.html`) |
| Скрипты | jQuery 3.6, slick (слайдер), fancybox (лайтбокс), jQuery UI + touch-punch (шторка), собственные `main.js` и скролл-анимации |
| Стили | обычный CSS шаблона, свои шрифты через `@font-face` |

`npm install` и сборка не нужны — достаточно раздать каталог любым статическим
сервером.

## Запуск локально

```bash
./serve.sh          # http://localhost:8000/
./serve.sh 9000     # другой порт
```

Открывать **по http://**, а не двойным кликом по `index.html`. Через `file://`
браузер заблокирует часть загрузок. Подойдёт любой статический сервер:

```bash
python3 -m http.server 8000     # то же, что serve.sh
npx serve .
php -S localhost:8000
```

## Публикация

**GitHub Pages.** Settings → Pages → Source: `Deploy from a branch`, ветка
`main`, каталог `/ (root)`. Файл `.nojekyll` уже лежит в корне — он
отключает Jekyll, чтобы тот не трогал статику. Сайт поднимется на
`https://<пользователь>.github.io/<репозиторий>/`; пути относительные, так что
подкаталог в URL ничего не сломает.

**Netlify / Vercel / Cloudflare Pages.** Build command оставить пустым,
publish directory — корень репозитория.

## Чем отличается от оригинала

Оригинал жил в `<iframe>` внутри демо-оболочки wedwed.ru: содержимое отдавал
`tloader.php`, а тексты, фотографии и запуск скриптов подставлял родительский
`viewer.js`. Здесь iframe убран, поэтому:

* **Переменные шаблона.** Скрипты читают `parent.d_mdate`, `parent.offsections`,
  `parent.demo_view` и т.п. Вне iframe `parent === window`, так что они просто
  объявлены глобально в `<script>` в `<head>` — там же имена, дата и `demo_view`.
* **Запуск.** `viewer.js` вызывал `iframe.contentWindow.initAll()`. Его заменяет
  короткий бутстрап перед `</body>`; он же держит скрытый `div.ct-demonstration`,
  по которому шаблон понимает, что нужно показать шторку-опенер, подключить
  скролл-анимации и fancybox.
* **Замороженный DOM.** Ctrl+S сохранил страницу уже «прокликанной»: шторка была
  сдвинута, слайдер пожеланий инициализирован slick'ом вместе с клонами слайдов.
  Это откачено к исходной разметке — иначе slick падал при повторной
  инициализации.
* **Пути.** В оригинале абсолютные (`/sitemaker/...`), здесь относительные —
  ради работы в подкаталоге.
* **Анкета.** Кнопка «Отправить» слала POST на `/sitemaker/ajax_alpha.php`.
  Бэкенда нет: гость по-прежнему видит «Спасибо», а данные пишутся в консоль
  браузера. Чтобы принимать ответы, нужен свой обработчик по этому адресу
  (поля `action, answer, project, data, company, alco, quest`).

## Что поправить под себя

| Что | Где |
|---|---|
| Имена, дата | `<script>` в `<head>` (`d_groom`, `d_bride`, `d_mdate`) и текст в разметке |
| Тексты блоков | атрибуты `data-sm-text` в `index.html` — текст лежит рядом, в самом теге |
| Фотографии | `sitemaker/userdata/58491/<project>/images/`, splash — `sitemaker/templates/template26/img/splash-photo.jpeg` |
| Телефон, ссылки | `href="tel:..."`, ссылка на карту Яндекса, вишлист — по тексту `index.html` |
| Кнопка 2ГИС | ссылка в `<a id="btn-2gis">`; адрес задан поиском, можно заменить на точку `https://2gis.ru/moscow/geo/<долгота>,<широта>` |
| Кнопка календаря | файл `wedding.ics` и ссылка в `<a class="sm-cal-link">` (Google Календарь) |
| Подпись «Made with love» | строка с `sm-madewithlove` в скрипте внизу `index.html` |
| Шрифт заголовков | `sitemaker/css/fontcss/cormorant_garamond.min.css` — объявляет псевдоним `SMHeadersFont`; подключён строкой `<link id="headerStyle">` |
| Шрифт текста | `sitemaker/css/fontcss/gilroy.min.css` — псевдоним `SMTextsFont`, `<link id="textStyle">` |

**Таймер и календарь.** Заполняются из `d_mdate` автоматически. Важная
особенность `main.js`: дата берётся, только если её год не меньше текущего —
иначе подставляется запасное значение шаблона (23 сентября) и обратный отсчёт
встаёт на нуле. Так что дату нужно держать в будущем.

Названия месяца и года в разметке при этом статичны: если меняете `d_mdate`,
поправьте заодно `data-sm-day`, `data-sm-tmonth-rod`, `data-sm-fyear` в первом
экране и `data-sm-fyear` / `data-sm-tmonth` в блоке с календарём.

**Кнопки «Открыть в 2ГИС» и «Добавить в календарь».** Обе работают без JS —
в `href` лежат обычные ссылки. Скрипт внизу `index.html` только подменяет ссылку
2ГИС на `intent://` в Android: система откроет приложение, а если его нет, Chrome
уйдёт на `browser_fallback_url` без окна ошибки. На iOS и десктопе остаётся
https-ссылка — установленное приложение перехватывает её само. Схему `dgis://`
намеренно не используем: когда приложения нет, Safari показывает ошибку.

Событие лежит в `wedding.ics` (31.10.2026, 14:30–22:00 МСК, время записано в UTC,
напоминание за сутки). iOS и macOS открывают такой файл сразу в «Календаре»,
Android скачивает и предлагает импорт, поэтому рядом стоит вторая, более
привычная для Android ссылка на Google Календарь.

> При смене даты правьте **три** места: `d_mdate` в `<head>`, `DTSTART`/`DTEND`
> в `wedding.ics` и параметр `dates=` в ссылке на Google Календарь. Время конца
> (22:00) взято по умолчанию — поменяйте, если нужно.

**Шрифты.** Заголовки — Cormorant Garamond 400 (Google Fonts, OFL 1.1), текст —
Gilroy. Оба подключены через псевдонимы `SMHeadersFont` и `SMTextsFont`, на которые
завязаны классы шаблона, так что шрифт меняется подменой одного файла — разметку
трогать не нужно. Cormorant разбит по подмножествам Unicode: браузер качает только
нужную часть, кириллица весит 12 КБ. Исходный Caravan (`caravan_big.min.css` и
`Caravan_big.*`) оставлен в репозитории — чтобы вернуть его, достаточно переключить
`href` у `<link id="headerStyle">` обратно.

## Права

Шаблон, шрифты, скрипты и изображения принадлежат wedwed.ru и авторам
использованных библиотек. Это личная офлайн-копия конкретного приглашения,
а не самостоятельный продукт.
